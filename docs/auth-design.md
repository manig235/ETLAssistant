# 인증 설계: ChatGPT 로그인, 기기 코드, API 키

작성: 2026-11-19. Codex rust-v0.170.0. 아래에서 **검증됨**은 이 폰에서 실제로 해 본 것, **미검증**은 코드는 있지만 아직 기기에서 안 돌려 본 것이다.

## 문제

Phase 0에서 `codex login --device-auth`로 로그인할 때 겪은 불편:

1. 로그에서 코드를 읽어 직접 타이핑해야 했다. 하이픈 포함 9자(`XXXX-XXXX`)인데 "8자인데 9자를 입력하라고 한다"는 혼란이 있었다.
2. 브라우저로 나가면 앱이 백그라운드가 되어 앱의 DNS가 막힌다(포그라운드 서비스로 해결, **검증됨**).
3. 완료 후 앱으로 돌아오는 길이 없다.
4. CLI 출력을 정규식으로 긁어 URL을 얻는 방식이라 출력 형식이 바뀌면 깨진다.

## 결정

### 1. 기본은 "브라우저로 로그인"(`account/login/start`, `type: "chatgpt"`) — 코드 입력이 없다

기기 코드 방식은 키보드가 없는 기기(서버, SSH)를 위한 것이다. **폰은 브라우저가 같은 기기에 있으므로** 로컬호스트 콜백 방식이 맞다.
사용자는 ChatGPT에 로그인하고 승인만 누르면 되고, 코드를 옮겨 적을 일이 없다.

- Phase 0에서 이 방식의 콜백(`127.0.0.1:1455`)까지는 도달했고, 당시 실패는 백그라운드 DNS 때문이었다. 포그라운드 서비스를 넣은 뒤 앱의 "브라우저로 로그인"으로 끝까지 가는 것을 사용자가 확인했다 → **검증됨**.
- 콜백 포트(1455)를 다른 앱이 쓰고 있으면 실패할 수 있다 → 기기 코드 방식을 폴백으로 둔다.

### 2. 폴백은 "기기 코드"(`type: "chatgptDeviceCode"`) — 코드를 옮겨 적지 않게 만든다

`account/login/start`가 `userCode`와 `verificationUrl`을 **구조화해서** 돌려주므로 CLI 출력 파싱이 필요 없다.

구현한 개선(설정 화면, **미검증**):
- 코드를 **크게(30sp, 고정폭, 글자 간격)** 보여 준다.
- 로그인을 시작하면 코드를 **클립보드에 자동 복사**한다(`EXTRA_IS_SENSITIVE`로 미리보기에서 가림). 브라우저의 입력칸에 **붙여넣기**만 하면 된다.
- "코드 복사", "브라우저 다시 열기", "취소" 버튼, **15분 남은 시간 표시**, "하이픈 포함 9자"라는 안내.
- 완료되면 앱이 백그라운드여도 **"로그인이 완료됐습니다" 알림**을 띄워 탭하면 돌아온다(알림 권한이 있을 때).

확인할 것: `verificationUrl`에 코드가 미리 채워져 있는지(RFC 8628의 `verification_uri_complete`). 그렇다면 붙여넣기도 필요 없다.
바이너리에 `verification_uri_complete` 문자열은 있으나 이 응답에 담기는지는 **미확인**이다.

### 3. API 키는 "고급, 선택" — 기본으로 권하지 않는다

| | ChatGPT 계정 | API 키 |
|---|---|---|
| 비용 | 본인 ChatGPT 플랜 한도 안(추가 요금 없음) | **쓴 만큼 본인 OpenAI 계정에 청구** |
| 프로젝트 원칙 | "무료, 서버 없음, 기기 내 실행"에 부합 | 사용자가 켜야만 쓰는 선택지로만 부합 |
| 배포 조건 | OpenAI의 "Sign in with ChatGPT" 오픈소스 경로(무료·오픈소스·기기 내 실행 앱 대상) | 해당 없음(사용자가 직접 비용 부담) |
| 필요한 사람 | 대부분 | ChatGPT에 Codex를 쓸 플랜이 없거나 한도가 부족한 사람 |

설계:
- **키는 우리 Keystore(AES-GCM)에만 둔다.** eTL 토큰과 같은 `SecretStore`(별칭 `openai_api_key_key`). 화면에는 `sk-…abcd`처럼 끝 4자리만 보인다.
- **Codex에는 `OPENAI_API_KEY` 환경변수로만 넘기고, `account/login/start`의 `apiKey`로 `auth.json`에 저장하지 않는다.** `auth.json`은 평문 파일이라 키가 남으면 우리 암호화가 무의미해진다. 환경변수로 주면 Codex가 `auth is provided by environment`로 쓴다(바이너리 문자열로 확인, 동작은 **미검증**).
- **환경에 이미 있는 키는 쓰지 않는다**(`OPENAI_API_KEY`, `CODEX_API_KEY`를 먼저 지우고 우리 값만 넣는다). 로그에는 `***`로만 찍는다.
- 설정에서 "API 키로 사용"을 켜야만 쓴다(`authMode`). 키만 저장해 두는 것으로는 과금이 시작되지 않는다. 켜거나 끄면 세션을 재시작한다.
- 화면에 **과금 안내문**을 둔다. 앱은 지출 한도를 걸 수 없으므로, 사용자가 OpenAI 쪽 프로젝트에서 월 한도를 걸라고 안내하는 것이 맞다(문구는 마법사에서 보강).
- 위험: 환경변수는 같은 UID 프로세스와 root만 읽는다. 폰의 앱 샌드박스 안에서는 허용 가능한 수준이다.

확인할 것(**미검증**): API 키 모드에서 쓸 수 있는 모델과 `code_mode_only` 여부(ChatGPT 계정 모드와 카탈로그 적용이 다를 수 있다). 다르면 호스트가 필요 없을 수도 있다.

### 4. ChatGPT 토큰은 앱이 암호화 보관한다 (2026-11-24 변경)

구버전의 평문 `CODEX_HOME/auth.json` 저장을 중단했다. `ChatGptOAuth`는 고정 Codex rust-v0.170.0의 OAuth PKCE·기기 코드·갱신 프로토콜을 사용한다.
고정 HTTPS 인증 호스트만 허용하고 리다이렉트는 따라가지 않는다. 로그인 콜백은 loopback과 임의 state를 확인한다.
`ChatGptSecretStore`는 Android Keystore AES-GCM으로 암호화하고 동기 저장한다. `ChatGptAuthStorage`는 기존 파일을 암호화한 뒤
복호화 검증을 통과해야 원본을 지운다. 전환 실패 시 실행을 중단하며 평문을 실행 중 복원하는 방식은 쓰지 않는다.

Codex는 설정과 CLI override 모두 `cli_auth_credentials_store="ephemeral"`을 사용한다. 앱이 stdio의 `account/login/start(chatgptAuthTokens)`로
접근 토큰을 주고, `account/chatgptAuthTokens/refresh` 요청에 갱신 결과를 전달한다. 갱신 토큰은 Codex에 전달하지 않는다.
이 프로토콜은 고정 버전의 experimental API이므로 Codex 버전 변경 시 함께 검증해야 한다. 로그인 완료·취소·로그아웃·갱신은
세대 확인과 직렬 처리로 오래된 인증 결과가 다시 적용되지 않게 한다. 로그아웃은 암호문과 해당 Keystore 키를 제거한다.
앱 데이터 백업과 기기 간 이전은 계속 제외한다. 정상 인증에 필요한 OpenAI 전송과 실행 중 메모리상의 토큰까지 없애는 기능은 아니다.

## 화면 흐름 (구현됨, 일부 미검증)

```
채팅 화면
  ├ 배너: eTL 토큰 없음 / 로그인 필요 / 준비 중 / 시작 실패(누르면 재시도)
  └ 설정
      ├ ChatGPT 계정: [브라우저로 로그인] [기기 코드로 로그인] [로그아웃]
      │    └ 로그인 패널: 코드(크게), [복사] [브라우저 다시 열기] [취소], 남은 시간
      ├ OpenAI API 키(고급): 입력·저장·삭제, "API 키로 사용" 체크, 과금 안내
      └ eTL 토큰: 입력·저장·삭제, "토큰 만들러 가기"(브라우저)
```

세션은 설정을 바꾸면(토큰 저장, 인증 방식 변경) 자동으로 재시작해 MCP 서버 등록과 `OPENAI_API_KEY` 전달을 갱신한다.

## 이전 로그인 구현의 검증 이력

아래 기록은 암호화 이전의 Codex 내장 로그인 기준이다. 새 앱 소유 OAuth의 검증 결과는 `docs/release.md`에 별도로 기록한다.

| 항목 | 상태 |
|---|---|
| ChatGPT 계정으로 채팅(스트리밍, 도구 호출, 저장) | **검증됨** |
| `account/read`로 로그인 상태 판별 | **검증됨**(로그인된 상태에서 채팅 화면이 배너 없이 열림) |
| 브라우저 로그인 `account/login/start(chatgpt)` 끝까지 | **검증됨**(사용자가 폰에서 직접 확인: "제대로 됨". 로그와 화면은 보지 못함) |
| 기기 코드 로그인과 클립보드 자동 복사, 알림 | 미검증 |
| `verificationUrl`에 코드가 포함되는지 | 미확인 |
| API 키 환경변수 전달로 Codex 인증 | 미검증 |
| API 키 모드의 모델/code mode 요구사항 | 미확인 |

## 남은 질문

- OpenAI SIWC 오픈소스 경로가 모바일 앱과 Play 스토어 배포에도 적용되는지(CLAUDE.md 미해결 질문과 같음). API 키 경로는 이 제약과 무관하다.
- 학생 대부분이 Codex를 쓸 수 있는 ChatGPT 플랜을 가졌는지. 없다면 API 키 경로가 사실상 유일한 선택이 되어 "무료" 원칙이 흔들린다.
