# 배포(GitHub Release)와 업데이트 알림

2026-11-22 사용자 결정: 업데이트가 잦아서 APK를 GitHub Release로 올리고, 영민이가 직접 새 버전을 확인해 알린다(Obtainium은 쓰지 않는다).

## 0.3.7 (2026-11-28)

- 성적 통계를 추가했다. eTL 과제·성적 공지의 평균·점수 분포를 기기에 저장하고, 성적 통계 화면·알림·비서 도구에서 본인 점수의 위치를 범위로 어림한다. 평균만 있으면 평균과의 차이만 안내하며 정확한 등수를 추측하지 않는다. 개인정보처리방침에 저장·삭제 동작을 반영했다.
- 비서의 이미지 생성 완료 결과를 해당 대화의 이미지 첨부로 연결한다. 저장된 이미지가 있어도 채팅에 나타나지 않던 문제를 고쳤으며, 구형 엔진의 인라인 PNG·GIF도 저장해서 미리보기·공유·대화 복원에 사용한다. 외부 경로와 심볼릭 링크를 통한 경로 탈출은 거부하고, 생성 파일도 14일 작업 파일 정리 대상에 포함한다.
- eTL 연결에 서울대 로그인으로 토큰을 만드는 화면을 추가했다. 토큰 API를 제공하지 않는 eTL에서는 웹 설정 경로로 안내한다.
- 시험 기본 알림을 칩으로 표시하고 삭제할 수 있게 했으며, 전날 20:00 → 시작 2시간 전 순서로 정렬한다.
- 여러 날에 걸친 종일 캘린더 일정의 저장·읽기를 보강했다. 대화 목록의 이름 바꾸기·지우기 버튼 위치를 맞추고 첫 화면에 보조 영문 이름 Young Mini를 표시한다.
- PDF는 파일 만들기가 켜져 있으면 확인 창 없이 생성한다. 파일 만들기 끔은 계속 적용한다.
- 내장 Codex는 rust-v0.170.0을 유지한다. 실제 기기에서의 이미지 생성→채팅 표시 재확인은 별도다.

0.3.7은 versionCode 26.

## 0.3.6 (2026-11-27)

- 파일 탭 숨김과 공지 출처 인식을 이유로 다운로드를 차단하던 앱의 조건을 제거했다. 서버가 단건 조회·다운로드를 허용하면 바로 읽고, 실패하면 과목 파일 → 공지·게시판 첨부/본문 링크로 이어 시도한다. `/files?preview=…` 링크와 파일 이름 없는 xlsx도 지원한다. 실제 해당 게시물의 서버 응답은 확보하지 못했으므로 기기 재확인은 별도다.
- AI 모델 ‘자동’에서 ChatGPT 계정의 모델 사용 거절이 발생하면 6.1 Sol을 우선 후보로 다른 모델을 최대 두 번 더 시도한다. 같은 실행 중 성공한 모델을 기억하고 거절된 모델은 피한다. 직접 선택한 모델은 자동으로 바꾸지 않는다.
- 모델 재시도는 원래 대화에서 이어 가며 사용자 메시지·첨부 카드를 중복 추가하지 않는다. 도구 또는 답변이 시작됐거나 사용자가 중지·삭제한 경우에는 재전송하지 않는다. 연결·로그인·사용량 한도 오류도 재시도 대상이 아니다.
- 같은 오류가 `error`와 `turn/completed`에서 두 번 표시되던 문제를 고쳤다. 재시도 전 모델의 늦은 응답은 무시한다.
- 내장 Codex는 계속 rust-v0.170.0이다. 실제 계정의 6.2 Sol 사용 가능 여부를 바꾸는 수정은 아니며, 모델 거절 시 대체 처리를 추가했다. 해당 기기의 실서버 재확인은 별도다.

0.3.6은 versionCode 25.

## 0.3.1 (2026-11-24)

- 답변 전체 복사 버튼을 추가하고, 비서가 읽은 참고 자료와 PDF 쪽 미리보기는 접어서 표시한다. 파일 카드의 열기·공유 동작을 정리했다.
- 알림·일정·위젯의 eTL 링크가 LearningX로 연결되도록 통일하고, 새 강의자료 알림에 "자료 받아줘" 동작을 넣었다.

- MCP 인증을 본문 처리보다 먼저 확인하고, 잘못된 청크·중복 헤더·과도한 연결을 거부한다. 프록시 인증정보가 후속 HTTP 요청으로 전달되지 않게 하며 사설망 목적지를 차단한다.
- eTL 인증 헤더는 원본 호스트에만 붙인다. 오류 응답을 정해진 문구로 제한하고, 도구 결과의 인증 필드·현재 토큰·알려진 서명 링크를 모델에게 보내기 전에 가린다.
- 비서의 일반 셸 실행·외부 웹 검색·범용 이미지 읽기를 끈다. 작업 폴더만 읽는 `etl_view_image`는 이미지 크기를 제한하고 원본 메타데이터를 제거한다.
- code-mode host는 네트워크 포트를 열지 않고 Codex가 private stdio 파이프로 직접 실행한다. 원본 다운로드는 보존하며, 검증한 고정 SHA의 ELF에서 같은 길이 helper 이름만 빌드 시 치환한다. 업그레이드로 SHA가 바뀌면 빌드는 중단된다. `assets/codex-runtime.json`에 변경 전후 SHA를 남긴다.
- ChatGPT OAuth 정보도 Keystore로 암호화하고, Codex는 ephemeral 인증만 사용한다. 레거시 평문 파일은 암호화 확인 후 삭제하며 실패 시 시작을 중단한다. 토큰 갱신·취소·로그아웃 경합을 방어한다.
- 내 마감·보강/휴강·캘린더 변경은 앱의 확인 창에서 승인한 호출만 실행한다. 화면 이탈·취소·시간 초과·턴 종료 후의 승인은 사용할 수 없다.
- 캘린더 정리에 실패하면 추적 정보를 유지하고 대상 변경을 중단한다. 되돌리기 기록의 식별자·역순 복원을 보강했다.
- 알람은 저장된 정보로 직접 알림을 처리하고 네트워크 갱신은 별도 작업으로 넘긴다. 정확한 알림은 사용자가 특별 접근을 허용할 때 쓰며, 미허용·절전 제한 상태에서 지연 상한을 약속하지 않는다.
- 앱 전용 작업 사본은 앱 시작·주기 작업에서 정리하고, 대화 삭제 시 다른 대화가 참조하지 않는 첨부 사본도 삭제한다. OS가 작업을 미루면 실제 삭제도 늦어질 수 있다.
- 개인정보처리방침을 실제 외부 전송·보관·삭제 동작에 맞추고, 빌드한 APK에 원문을 포함하여 첫 안내와 설정에서 오프라인으로 표시한다.
- AGP를 8.13.2로 올려 Kotlin 2.3을 지원하는 R8을 사용한다([공식 릴리스 설명](https://developer.android.com/build/releases/agp-8-13-0-release-notes)).
- 검증: 단위 테스트 669개 통과·1개 제외, 릴리스 Lint 오류 0개·경고 178개·힌트 7개. 릴리스 APK 빌드와 v2/v3 서명 검증을 통과했고, APK의 처리방침·네이티브 바이너리 SHA가 원문·빌드 기록과 일치한다.
- 데스크톱의 고정 Codex 바이너리로 모의 Responses 요청→code-mode JS 실행→결과 전달을 검증하고 helper가 소유한 TCP 소켓이 없음을 확인했다. `scripts/test-codex-private-transport.py`로 재현한다.
- 사용자 승인 후 연결된 실기기의 개발용 서명 앱을 데이터 유지 업데이트했다. 기존 auth.json 제거·암호문 생성·기존 로그인 세션 준비를 확인했다. `SecuritySmokeInstrumentation`은 실제 ARM helper의 `grpc+stdio://` 실행 인자·stdin/stdout 파이프·JS 실행, Keystore 암호화·레거시 이전·키 삭제, Android 이미지 회전·EXIF 제거·경로/심볼릭링크 거부를 합성 데이터로 검증했다. Android의 `/proc/net` 제한 때문에 소유 TCP 소켓 대조는 데스크톱에서만 수행했다. 계정·토큰·대화 원문은 검증 출력에 남기지 않았다.

0.3.1은 versionCode 20으로 GitHub에 직접 배포한다. 기기 검증에는 기존 데이터 보존을 위해 기존 설치본과 같은 개발용 서명을 사용했고, 배포용 서명 APK는 별도로 검증했다. 새 OAuth의 브라우저/기기코드 첫 로그인은 실제 계정으로 끝까지 수행하지 않았으며, 절전/재부팅 알림과 캘린더 권한 회수/복구의 장기 실기기 확인도 별도다. 개인정보처리방침 1.1을 APK와 공개 저장소에 포함한다.

## 0.2.8 (2026-11-23)

- 일정 위젯의 공간 활용·구분선·여백과 시간표 가독성을 개선하고 일정 2×1·시간표 4×6·다음 수업 2×1, 설정의 위젯 추가 메뉴를 제공한다.
- 수식 주변 문장 선택·원문 복사·넓은 수식 이동을 수정했다. eTL 알림은 원문을 바로 열며 누락된 링크를 ID로 복원한다. 브리핑은 앱을 연다.
- 시작 질문 여섯 개를 제공하고, 과목별 질문은 3~4학점과 실제 자료·최근 과제 유무를 확인해 고른다. 설정 업데이트 버튼과 여러 안내 문구를 정리했다.
- 검증: 단위 테스트 435개 통과·기존 제외 1개, Lint 오류 0건. 앞선 로컬 APK에서 위젯 추가·수식 선택 등을 실측했다. 최종 자료·과제 존재 조건은 단위 테스트와 빌드를 완료했으며, 추가 실기기 확인은 사용자 요청으로 생략했다.

## 앱 쪽 동작 (`update/`)

- `GET https://api.github.com/repos/manig235/ETLAssistant/releases/latest` 하나만 보낸다. 토큰·계정·기기 정보 없음,
  User-Agent `youngmin-android`, 연결 8초/읽기 10초, 리다이렉트 안 따라감, 응답 512KB 상한.
- 언제: 채팅 화면을 열 때(마지막 확인 후 6시간이 지났으면) + `UpdateCheckWorker` 하루 한 번(네트워크 제약 없이 예약: 앱 UID 네트워크가 막히면 CONNECTED 작업은 시작되지 않는다. 알림 확인 워커와 별개).
  재부팅·앱 업데이트 때 `SystemEventReceiver`가 다시 예약한다.
- 초안·사전 배포(prerelease)는 무시한다. 태그는 `v<숫자.숫자…>`만 읽고 지금 versionName과 숫자 단위로 비교한다.
- 알림 채널 `update_v2`("앱 업데이트", HIGH), 버전마다 한 번. 0.2.3부터 알림·채팅 팝업의 "받기"·설정의 새 버전 링크를 누르면
  확인한 태그의 APK 직접 다운로드 주소(`https://github.com/manig235/ETLAssistant/releases/download/<태그>/<파일>.apk`)를 연다.
  Release 페이지를 거치지 않고 브라우저가 APK를 다운로드하며, 설치는 사용자가 받은 파일을 열어 진행한다.
- APK 파일 이름을 확인 결과에 함께 저장한다. 앱은 `youngmin-v<버전>.apk`를 선택하며, 버전 없는 별칭이 먼저 나와도 고르지 않는다.
  이전 저장값의 파일 이름이 없거나 `youngmin.apk`이면 배포 규칙(`youngmin-v<버전>.apk`)으로 복원한다.
  APK가 없는 릴리스는 업데이트로 안내하지 않고, 다른 저장소·APK가 아닌 파일·경로 이동이 들어간 링크는 열지 않는다.
- 설정: "기타 → 업데이트 알림"(기본 켬, 끄면 워커 취소·앱 시작 확인 안 함), 앱 정보의 단일 업데이트 버튼(통합 변경은 0.2.8).
  "업데이트 확인" → "확인하는 중…" → 새 버전이 있으면 같은 버튼이 "새 버전 0.2.x 받기"로 바뀌고 해당 APK를 연다. 직접 확인은 업데이트 알림이 꺼져 있어도 동작한다.
- 0.2.5부터 수동 확인 결과에 설치된 버전과 최신 공개 버전을 표시하고,
  요청에 `Cache-Control: no-cache`를 보낸다. 응답을 해석하지 못했거나 APK가 없거나 404이면 확인 실패로 표시하며 "최신"으로 처리하지 않는다.
- 0.2.3의 변경은 APK 직접 다운로드에 관한 것으로 버전 감지와는 별개다. 같은 버전은 업데이트로 알리지 않으며,
  이미 배포한 APK를 고칠 때는 versionName·versionCode를 모두 올려 새 태그로 배포한다.

## 릴리스 규칙

- 태그: `v<versionName>` (예: `v0.1.8`). 버전 올림 커밋을 main에 push한 뒤 그 커밋에 태그를 단다.
- 제목: `영민이 <버전>`.
- asset: `youngmin-v<버전>.apk`와 `youngmin-v<버전>.apk.sha256`(`sha256sum` 출력 형식). `~/shared/`에 만든 것과 같은 파일.
- **사용자 요청(2026-11-23): 앞으로 다운로드 파일명은 반드시 버전을 포함한다.** 릴리스 본문·채팅 안내·앱 내 업데이트의 다운로드 링크는
  `…/releases/download/v<버전>/youngmin-v<버전>.apk`를 쓴다. `scripts/github-release.sh`도 이 링크를 본문에 자동으로 넣는다.
- 버전 없는 `youngmin.apk`는 이미 공유된 고정 링크를 위한 호환용으로만 올린다(`~/shared/youngmin.apk`, sha256 같음).
  새 다운로드 안내에는 버전 없는 고정 링크를 쓰지 않는다.
- 초안(draft)이나 사전 배포(prerelease)로 올리면 앱이 알리지 않는다. 시험할 때만 그렇게 쓴다.
- 반드시 전용 키(`~/.android/youngmin-release.jks`)로 서명한 release APK만 올린다. 다른 키면 기존 설치본 위에 업데이트되지 않는다.

## 절차

배포할 커밋의 main Android CI(단위 테스트·debug 빌드·Lint·서명 없는 R8)가 모두 통과했는지 확인한다.
PR에서는 단위 테스트·debug 빌드와 Lint가 별도 작업으로 실행되고 보고서는 7일 보관된다.
CI에는 배포 서명 키를 넣지 않으며, release APK 서명·업로드는 아래 절차대로 로컬에서 한다.

```
./gradlew testDebugUnitTest assembleRelease
cp app/build/outputs/apk/release/app-release.apk ~/shared/youngmin-v0.1.8.apk
(cd ~/shared && sha256sum youngmin-v0.1.8.apk > youngmin-v0.1.8.apk.sha256)
cp ~/shared/youngmin-v0.1.8.apk ~/shared/youngmin.apk
git push origin main
gh release create v0.1.8 ~/shared/youngmin-v0.1.8.apk ~/shared/youngmin-v0.1.8.apk.sha256 ~/shared/youngmin.apk \
  --target main --title "영민이 0.1.8" --notes-file notes.md
# gh가 없으면: GITHUB_TOKEN=… scripts/github-release.sh 0.1.8 notes.md (youngmin.apk는 웹에서 추가) 또는 GitHub 웹에서 같은 규칙으로
```

`GITHUB_TOKEN`은 이 저장소에 contents 쓰기 권한이 있는 fine-grained 토큰. 저장소·셸 기록에 남기지 않는다(예: `read -s GITHUB_TOKEN; export GITHUB_TOKEN`).
